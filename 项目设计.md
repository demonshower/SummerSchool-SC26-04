# 出差行程规划助手 — 项目设计

## 设计思路

本项目基于 Vibe Coding 方式开发，目标是实现一个出差行程规划助手，核心围绕三个方向展开：

- **行程规划**：根据用户设定的城市、日期、会议和预算，自动化获取目的地可用资源（交通、住宿、景点、餐饮），筛选并编排为每日日程。
- **旅游规划**：自动获取平台旅游攻略和 POI 库信息，整理汇总为可供参考的出行方案，辅助用户做目的地决策。
- **个性化风格**：将用户的旅游偏好（交通方式、酒店档次、观光偏好、行程节奏）持久化沉淀，逐步形成个性化旅游风格，自动影响后续规划结果。

## 2. 行程规划设计

> 行程全生命周期管理、日程编排、自动规划与费用控制。

### 2.1 模块概览

```
TripsModule ────── 行程 CRUD + 会议 + 费用汇总
ItineraryModule ── 活动项管理 + 锁定/排序 + 日费用同步
PlanningModule ─── 规则引擎：日期分析 → 交通/酒店/活动生成
```

### 2.2 行程数据模型

```
Trip (聚合根)
  ├── TripMeeting[]          # 会议（标题/日期/时间/地点/经纬度）
  ├── TripDay[]              # 每日分组（dayType/预算/实际费用）
  │     └── ItineraryItem[]  # 活动项（8 种 kind/position/locked/version）
  │           └── TransportSegment  # 交通详情（站名/承运商/时长/距离）
  └── PlanVersion[]          # 规划版本（版本号/策略/状态）
```

### 2.3 活动项模型（ItineraryItem）

```
ItineraryItem
├── 8 种 kind: transport / commute / hotel / meal / attraction / meeting / fixed / free_time
├── position:     该天内的排序位置
├── locked:       锁定标志（系统关键项禁止编辑/删除）
├── isFixed:      固定项标志（不可拖动）
├── placeId:      关联 Place 表（可选）
├── costMinor:    费用（分）
├── version:      乐观锁版本号
└── transportSegment: 1:1 关联（仅 kind=transport 时存在）
    ├── mode: train / flight / bus ...
    ├── fromStation / toStation
    ├── departureTime / arrivalTime
    ├── durationSeconds / distanceMeters
    ├── carrierName / carrierCode
    └── costMinor
```

### 2.4 费用汇总数据流

```
用户查看行程详情
  → TripsService.findOne()
    → 查询 Trip + meetings + days + items + quoteSearches + planVersions
    → calculateCostSummary(trip)
        │
        ├── 遍历 trip.days[].items[]
        │     ├── kind=transport  → transportMinor
        │     ├── kind=hotel      → hotelMinor
        │     ├── kind=meal       → mealMinor
        │     ├── kind=commute    → commuteMinor
        │     └── kind=attraction → attractionMinor
        │
        ├── totalMinor = sum(以上五类)
        ├── remainingMinor = budgetMinor - totalMinor
        └── 预算状态:
              remaining >= 0                  → within_budget
              -10% <= ratio < 0               → close_to_budget
              -30% <= ratio < -10%            → slightly_over
              ratio < -30%                    → over_budget
```

### 2.5 自动规划引擎

**总体流程**：

```
createPlan(trip, strategy)
  │
  ├── 1. trip.status = 'planning'
  │
  ├── 2. analyzeDays(trip)  ── 逐日判定 dayType
  │     ├── 第一天   → departure
  │     ├── 有会议   → meeting_day
  │     ├── 最后一天 → return
  │     └── 其余     → free
  │
  ├── 3. calculateFreeSlots(date, meetings, dayType)
  │     全天窗口 [08:00, 22:00] - 会议占用时段 - dayType 调整
  │
  ├── 4. generateTransport(trip, analysis)
  │     出发/返程的 train 或 flight 项
  │
  ├── 5. generateHotels(trip, analysis)
  │     从 Place 表按城市名 + category=hotel 查询，结合 hotelMaxPriceMinor 过滤
  │
  ├── 6. generateActivities(trip, analysis, strategy)
  │     从 Place 表按 category 查询景点/餐厅
  │     按 strategy + attractionPreference 评分排序
  │     填入 freeSlots，景点间插入餐饮
  │
  ├── 7. 事务写入数据库
  │     syncTripDays → batch insert ItineraryItem + TransportSegment
  │     → 创建 PlanVersion → trip.status = 'ready'
  │
  └── 错误回滚 → trip.status = 'draft'
```

**策略映射**：

| strategy | 酒店 | 餐厅 | 景点 |
|----------|------|------|------|
| budget | 经济型 | 平价 | 免费/低价优先 |
| balanced | 舒适型 | 中档 | 平衡选择 |
| comfort | 高端型 | 特色 | 热门/经典优先 |

### 2.6 活动项操作流程

```
createItem(dayId, kind, title, ...)
  → 验证 day 属于当前 trip
  → 未传 position → 自动置为末尾
  → INSERT item → updateDayCost(dayId) → trip.version++

updateItem(itemId, dto)
  → 验证 item 未 locked
  → 校验 item.version === dto.version（乐观锁）
  → UPDATE item → item.version++ → updateDayCost → trip.version++

deleteItem(itemId)
  → 验证 item 未 locked 且 !isFixed
  → DELETE item → updateDayCost → trip.version++

moveItem(itemId, toDayId, position/baseVersion)
  → 校验 trip.version === baseVersion
  → 验证 toDayId 存在
  → UPDATE dayId + position → trip.version++

lockItem(itemId, locked)
  → 设置 locked 标志 → trip.version++

reorderItems(items[], baseVersion)
  → 校验 trip.version === baseVersion
  → 事务批量 UPDATE position → trip.version++

updateDayCost(dayId)
  → SELECT SUM(costMinor) FROM items WHERE tripDayId = dayId
  → UPDATE trip_days SET totalCostMinor = sum
```

## 4. 个性化风格设计

> 用户认证、出行偏好与系统安全。

### 4.1 模块概览

```
AuthModule  ──── 注册/登录/游客 + JWT 签发与验证
UsersModule ──── 用户信息查询/更新
偏好设置    ──── 分散在 Trip 模型中的 transportPreference / pace / attractionPreference 等字段
```

### 4.2 认证流程

```
┌────────────┐     ┌──────────────┐     ┌─────────────┐
│   Next.js  │────▶│   NestJS     │────▶│  PostgreSQL │
│   frontend │     │   AuthModule │     │  users 表   │
└────────────┘     └──────────────┘     └─────────────┘

注册: username + password + email
  → AuthService.register()
    → 检查 username/email 唯一性
    → bcrypt.hash(password, 10)
    → INSERT users (passwordHash)
    → JWT sign({ sub: user.id, isGuest: false })
    → 返回 { user, accessToken }

登录: username + password
  → AuthService.login()
    → SELECT user WHERE username
    → bcrypt.compare(password, user.passwordHash)
    → JWT sign()
    → 返回 { user, accessToken }

游客: （无参数）
  → AuthService.guestLogin()
    → 生成 username = "guest_{timestamp}_{random}"
    → INSERT users (isGuest=true, passwordHash=随机哈希)
    → JWT sign({ sub: user.id, isGuest: true })
    → 返回 { user, accessToken }

前端持久化:
  localStorage['auth-storage'] ← Zustand persist({ token, user, isAuthenticated })
  Axios 请求拦截器 → headers.Authorization = `Bearer ${token}`
  401 响应拦截器 → localStorage.clear() → router.push('/auth/login')
```

### 4.3 JWT 验证链

```
请求到达 NestJS
  → AuthGuard('jwt') 激活
  → JwtStrategy.validate(payload)
    → 从 Authorization Header 提取 Token
    → jwt.verify(token, secret) 验证签名的过期时间
    → 解析出 { sub: userId, isGuest }
    → UsersService.findById(userId)
      → SELECT user WHERE id = userId AND deletedAt IS NULL
      → 将 user 对象挂载到 request.user
  → Controller 中通过 @CurrentUser() 或 @CurrentUser('id') 获取
```

### 4.4 出行偏好模型

偏好字段分布在 Trip 表中，影响规划引擎的行为：

```
Trip 偏好字段:
  ├── transportPreference    (any / train / flight)
  │     └── 影响 generateTransport() 的交通方式选择
  ├── hotelMaxPriceMinor     (每晚上限，分)
  │     └── 影响 generateHotels() 的酒店过滤条件
  ├── attractionPreference   (any / nature / culture / food / shopping)
  │     └── 影响 generateActivities() 的景点评分权重
  ├── pace                   (relaxed / balanced / intense)
  │     └── 影响每日活动数量和间隔
  └── wantsSightseeing       (boolean)
        └── 为 false 时跳过活动生成

规划策略参数（CreatePlanDto）:
  └── strategy               (budget / balanced / comfort)
        └── 影响酒店档位、餐厅档次、景点选择的综合倾向
```

### 4.5 安全与并发控制

```
所有权校验:
  每个 Service 方法开头:
    const trip = await prisma.trip.findUnique({ where: { id: tripId } })
    if (trip.ownerId !== userId) throw new ForbiddenException()

乐观锁:
  编辑 Trip:
    const trip = await prisma.trip.findUnique({ where: { id } })
    if (dto.version !== undefined && dto.version !== trip.version)
      throw BusinessException.versionConflict(trip.version, dto.version)
    UPDATE trip SET ... version = version + 1

  编辑 ItineraryItem:
    同上逻辑, item.version 字段

规划回滚:
  async createPlan() {
    try {
      await prisma.trip.update({ data: { status: 'planning' } })
      // ... 规划逻辑 ...
      await prisma.trip.update({ data: { status: 'ready' } })
    } catch (e) {
      await prisma.trip.update({ data: { status: 'draft' } })
      throw e
    }
  }

软删除:
  User: deletedAt 字段标记删除时间
  查询: WHERE deletedAt IS NULL
  真实删除不执行，数据保留可追溯

操作日志:
  UserEvent 表:
    userId + eventType + entityType + entityId + context(JSON) + occurredAt
```


### 5.2 三大分类与数据表映射

| 分类 | 核心表 | 辅助表 |
|------|--------|--------|
| 行程规划 | trips, trip_meetings, trip_days, itinerary_items, plan_versions | transport_segments |
| 旅游规划 | places, cities, quote_searches, quotes, content_sources, place_mentions | — |
| 个性化风格 | users, user_events | trips (偏好字段部分) |

### 5.3 设计规范

| 规范 | 说明 | 示例 |
|------|------|------|
| 金额 | 整数存储最小货币单位，字段名 `xxxMinor` | `budgetMinor`, `costMinor` |
| 时间 | ISO 8601，库内 UTC，日期字段 `@db.Date` | `createdAt`, `startDate` |
| 外键 | `xxxId` 命名 + `ON DELETE CASCADE` | `ownerId`, `tripId` |
| 软删除 | `deletedAt` 字段 | User 表 |
| 乐观锁 | `version` INT 字段 | Trip, ItineraryItem |
| DB 映射 | 库内字段 `@map("snake_case")` | `@map("owner_id")` |
| ID | CUID 字符串 | `@id @default(cuid())` |

### 5.4 核心表字段概要

**Trip**（聚合根，14 个业务字段 + 版本 + 时区 + 货币）：

| 字段 | 类型 | 用途 |
|------|------|------|
| originCity / destinationCity | VARCHAR(50) | 起止城市 |
| startDate / endDate | DATE | 行程起止日期 |
| earliestDeparture / latestReturn | DATETIME | 最早出发/最晚返回时间 |
| budgetMinor | INT | 总预算（分） |
| transportPreference | VARCHAR(20) | 交通偏好 (any/train/flight) |
| hotelMaxPriceMinor | INT | 酒店每晚上限（分） |
| attractionPreference | VARCHAR(20) | 观光偏好 (any/nature/culture/food/shopping) |
| pace | VARCHAR(20) | 节奏 (relaxed/balanced/intense) |
| wantsSightseeing | BOOLEAN | 是否安排观光 |
| status | VARCHAR(20) | draft/planning/ready/confirmed/archived |
| version | INT | 乐观锁 |

**TripDay**（关联 Trip + Date，唯一约束 `(tripId, localDate)`）：

| 字段 | 类型 | 用途 |
|------|------|------|
| localDate | DATE | 当地日期 |
| dayType | VARCHAR(20) | departure/meeting_day/return/free |
| budgetMinor / totalCostMinor | INT | 预算/实际费用 |
| startPlaceId / endPlaceId | FK→Place | 当日起点/终点 |

### 6.3 状态管理策略

| 数据 | 方案 | 理由 |
|------|------|------|
| Token / User | Zustand + localStorage persist | 需跨页面共享 + 刷新不丢失 |
| 行程列表/详情 | TanStack Query cache | 自动缓存、失效重取、后台刷新 |
| 报价/攻略查询 | TanStack Query (enabled 延迟触发) | 用户点击后才发起请求 |
| 表单输入 | React Hook Form + Zod | 局部状态，无需全局 |
| UI 面板切换 | React useState | Tab/折叠/弹窗等局部交互 |

## 7. 安全设计

| 层面 | 措施 | 实现 |
|------|------|------|
| 传输 | Token 不存 Cookie，仅 Header 传递 | Axios 拦截器附加 `Authorization: Bearer <token>` |
| 存储 | 密码 bcrypt(cost=10) 不可逆 | `auth/auth.service.ts` |
| 认证 | JWT 7 天过期 + 每次校验从数据库加载最新用户状态 | `auth/strategies/jwt.strategy.ts` |
| 授权 | 每个业务接口校验 `ownerId === userId` | 各 Service.verifyTripOwnership() |
| 输入 | ValidationPipe(whitelist, forbidNonWhitelisted) + DTO 白名单校验 | `main.ts` + 各 dto 文件 |
| 输出 | 全局异常过滤 + 统一响应包装，不泄露内部错误 | `common/filters/` + `common/interceptors/` |
| CORS | 仅允许配置的白名单域名 | `main.ts`（`app.enableCors`） |
| 并发 | 编辑操作 version 乐观锁 | Trip.version / ItineraryItem.version |

## 8. 关键设计决策

| 决策 | 理由 |
|------|------|
| 金额整数存储（分） | 避免 JS 浮点运算精度问题 |
| CUID 主键 | 分布式友好，不可遍历，无需自增序列 |
| 乐观锁 version | 避免悲观锁的性能开销，冲突概率低的场景体验更好 |
| 报价请求 SHA256 缓存 | Mock 模式下减少重复计算，对接真实 API 时可节省调用次数 |
| 报价 append-only | 保留历史快照，支持价格趋势分析和审计回溯 |
| 规划失败自动回滚 | 保证 Trip 状态一致性，规划中异常不会卡在中间状态 |
| 前后端完全分离 | 独立开发/部署/扩展，技术栈解耦 |
| App Router (Next.js 16) | 最新路由范式，RSC 支持，与 React 19 生态对齐 |
| TanStack Query | 内置缓存/去重/后台刷新/乐观更新，减少手写状态管理 |
| NestJS 模块化 | 业务模块独立，依赖倒置，单一职责，便于测试和维护 |
